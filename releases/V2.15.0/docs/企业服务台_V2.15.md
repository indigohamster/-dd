# 企业服务台 V2.15 使用与验收说明

V2.15 的目标是把机器人已有的报修能力补成一条可以日常值班使用的服务台闭环：员工从钉钉选择服务或报告故障，系统保存服务类型与 SLA，运维在操作台处理，员工确认恢复并评分，确认后的解决方案再进入知识候选。

## 一、标准处理链路

```text
员工描述故障或选择服务目录
  → 创建事件/服务请求并固化服务项、处理组和 SLA
  → 运维分派、公开回复或记录内部备注
  → 运维标记解决（等待员工确认）
  → 员工确认恢复并评分 → 自动关闭 → 生成知识候选
                         ↘ 仍未解决 → 重新打开
```

`resolved` 表示方案已给出、等待用户确认；`closed` 才表示本次服务正式结束。这样可以分别统计“运维认为已处理”和“员工确认已恢复”。

## 二、员工钉钉命令

| 命令示例 | 用途 |
|---|---|
| `帮助`、`服务台`、`能做什么` | 打开服务台首页 |
| `服务目录`、`我要申请` | 查看当前启用的服务项及承诺时间 |
| `申请服务 ACCESS 申请财务共享目录只读权限` | 按服务目录创建结构化服务请求 |
| `报修 VPN 无法连接，错误 691` | 创建故障事件；信息不足时先进入问诊 |
| `我的工单` | 查看本人最近工单及处理状态 |
| `工单 TKT-20260720-001` | 查看本人单张工单、公开处理记录和 SLA |
| `补充 TKT-20260720-001 上午十点开始，三位同事都受影响` | 向工单补充用户可见信息 |
| `催办 TKT-20260720-001` | 记录催办并提醒处理人员 |
| `撤回 TKT-20260720-001 已自行解决` | 撤回尚未解决的误报或不再需要的请求 |
| `确认恢复 TKT-20260720-001 评分5 网络已稳定` | 验收解决结果、评分并关闭工单 |
| `重开 TKT-20260720-001 仍会间歇断线` | 解决结果无效时重新进入处理队列 |

工单编号不区分大小写，并会自动规范化空格。创建、撤回、归档等指令包含否定表达时不会执行反向操作。

## 三、服务目录

管理后台“服务目录”用于维护员工可申请或可报修的标准服务。每个服务项至少包含：

- 唯一编码、名称、事件/服务请求类型和启用状态。
- 分类、默认优先级、处理组、可选服务负责人和提交说明。
- 首次响应目标与解决目标，单位为自然小时。
- 可选的关键词和审批标识，用于后续扩展路由与审批连接器。

保存服务目录后，钉钉端会读取同一份设置，不需要修改代码。删除或停用服务项不会删除已经创建工单中的服务快照。

填写服务负责人 ID/名称后，员工或管理台按该服务建单会自动分派；失败时工单不会丢失，而是留在待分派队列并返回明确提示。

## 四、SLA 口径

V2.15 使用自然时间 SLA；工作日历、节假日暂停和供应商暂停留待后续版本。

- `response_due_at`：最晚首次响应时间。首次分派、开始处理或人工回复会写入 `first_response_at`。
- `resolution_due_at`：最晚给出解决结果时间。
- `normal`：目标时间充足。
- `at_risk`：剩余时间已进入预警区间。
- `breached`：首次响应或解决目标已经超时。
- `met`：工单已在目标内完成。

未选择服务目录时，系统按优先级采用默认 SLA；选择服务项时使用服务项中的目标，并在创建时写入工单，后续修改目录不会改变历史工单的承诺。

## 五、管理操作台

工单工作台支持组合筛选、分页、精确或关键词搜索、快捷队列、批量操作、CSV 导入导出以及单张工单时间线。常用快捷队列包括未分配、即将超时、已超时、待用户确认和重新打开。

处理记录分为：

- 内部备注：仅管理操作台和管理员可见，不发送给提交人。
- 公开回复：进入员工可见时间线，并通过工单通知送达提交人。

批量操作最多处理 100 张工单，逐张返回成功或失败原因；智能表格同步只排队一次。状态不允许的动作不会显示为成功。

首次初始化管理员可在本机“人员”页面填写钉钉 Staff ID，并将角色设为“工单管理员”；也可在 `config.yaml` 的 `ticket.admins` 中配置稳定 `user_id` 或 `staff_id`。系统不会按昵称授权，也不会把第一个发消息的人自动设为管理员。

## 六、用户验收与知识闭环

运维标记解决后，员工会收到确认指令。员工回复“确认恢复”后系统会：

1. 校验工单归属和当前状态。
2. 保存确认时间、1–5 分评分和可选评价。
3. 把工单状态切换为关闭。
4. 记录反馈和完整操作日志。
5. 将已验收的解决方案生成知识候选，进入人工审核流程。

只有包含解决方案、已确认关闭且未标记无效的工单可以进一步归档为经验；活跃、撤回或等待确认的工单不会被归档操作静默关闭。

员工回复“重开”时，系统保留原解决方案和失败反馈，工单重新进入处理中；该记录用于计算重开率并帮助识别低质量解决方案。

## 七、AI 表格字段

在原有工单字段之外，V2.15 可同步请求类型、服务代码、服务项目、处理组、首次响应/解决时限、首次响应时间、用户确认时间和满意度。目标 AI 表格没有对应可选字段时会在同步结果中提示，但不会阻止其他已映射字段同步；“工单编号”仍是唯一必需字段。

## 八、上线前验收清单

- 旧工单数据库自动迁移，原工单和时间线无丢失。
- 事件与服务请求在数据库、操作台、通知、导出和 AI 表格中保持一致。
- 每张新工单均保存 SLA 时间点；首次人工动作只记录一次首次响应。
- 员工无法查看或操作他人的工单，也看不到内部备注。
- 解决不会直接关闭；确认恢复可以保存评分并关闭，未恢复可以重开。
- 组合筛选的总数、分页和导出结果一致，批量操作能报告部分失败。
- 服务目录修改有配置历史，已创建工单仍保留原服务与 SLA 快照。
- 全量自动化测试、Python 编译检查、前端 JavaScript 语法检查和 EXE 构建全部通过。

## 九、当前边界

V2.15 定位为轻量企业 IT 服务台，不包含完整 CMDB、变更管理、问题管理、复杂审批编排、多租户和计费。目录中的审批标识用于提示与后续连接器扩展，当前仍由运维人员在工单中完成审批协作。
