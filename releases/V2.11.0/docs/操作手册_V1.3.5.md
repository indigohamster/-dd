## 一、系统概述

运维数字人是一款基于钉钉 Stream 长连接的智能运维助手，核心能力：

- 🔍 **IMA 知识库搜索** — 接入 5 个运维知识库（U9、售后、软硬件维护、网络维护），共 729+ 条知识
- 🤖 **DeepSeek AI 对话** — 基于知识库搜索结果，由 LLM 生成自然语言回答
- 📋 **工单系统** — 从问题反馈到工单创建、处理、归档的完整闭环
- 🔧 **专家模式** — 按领域切换知识库范围，精准回答

### 技术架构

| 组件 | 说明 |
|------|------|
| 钉钉 Stream SDK | WebSocket 长连接，实时接收群聊/单聊消息 |
| IMA 知识库 API | 腾讯 IMA 智能工作台，语义搜索 + RAG |
| DeepSeek LLM | `deepseek-chat` 模型，温度 0.3，最大 1024 token |
| CodeBuddy API | 本地 HTTP 服务，可切换为 AI 引擎 |
| SQLite (WAL) | 工单数据本地存储，`data/tickets.db` |

## 二、基础使用

### 2.1 与机器人对话

| 场景 | 方式 |
|------|------|
| **单聊** | 在钉钉搜索机器人名称，直接发消息 |
| **群聊** | 在群里 @机器人 + 消息内容 |

### 2.2 消息处理优先级

机器人按以下优先级处理消息：

```
1. 专家召唤触发词（"召唤XXX专家"）
2. 专家模式意图检测（退出/切换/列表）
3. 反馈回复检测（"是"/"否" 对 AI 回答的反馈）
4. 工单指令解析（创建/查看/解决/归档等）
5. 旧触发词搜索（"搜"/"查"/"找"）
6. 普通消息 → 知识库搜索 + AI 回答
```

## 三、专家模式

### 3.1 可用专家

| 触发词 | 说明 | 搜索范围 |
|--------|------|----------|
| **召唤运维专家** | 搜索全部默认知识库 | U9 + 售后 + 软硬件维护 + 网络维护 |
| **召唤U9专家** | 仅搜索 U9 问题处理知识库 | U9问题处理（184条） |
| **召唤售后专家** | 仅搜索售后服务知识库 | 日盛售后服务（485条） |

### 3.2 专家模式操作

| 操作 | 指令 |
|------|------|
| **召唤专家** | `召唤运维专家` / `召唤U9专家` / `召唤售后专家` |
| **带问题召唤** | `召唤U9专家 U9物料怎么查` |
| **切换专家** | `切换运维专家` / `切换售后专家` |
| **查看当前专家** | `当前专家` / `专家模式` / `还在专家模式吗` |
| **退出专家模式** | `退出专家` / `取消专家` / `退出模式` |

> ⏰ 专家模式 30 分钟未对话自动退出

### 3.3 旧触发词（兼容）

消息中包含 `搜` / `查` / `找` / `知识库` 也会触发知识库搜索，返回原始搜索结果（不经 AI 加工）。

## 四、工单系统

### 4.1 工单生命周期

```
🆕 open (待处理)
  ↓ 分配
📌 assigned (已分配)
  ↓ 开始处理
🔧 in_progress (处理中)
  ↓ 解决
✅ resolved (已解决)
  ↓ 归档             ↓ 标记无效
📚 archived (经验)    🚫 closed (无效)
```

### 4.2 工单编码规则

格式：`TKT-YYYYMMDD-NNN`

- `TKT` — 固定前缀
- `YYYYMMDD` — 创建日期
- `NNN` — 当日递增序号（001起，每天重置）

示例：`TKT-20260605-001`、`TKT-20260605-002`

> ⚠️ V1.3.5 起，每次反馈"否"都创建独立新工单，不同问题不会复用同一编号。

### 4.3 工单分类

| 分类 | 触发关键词 |
|------|-----------|
| U9C | U9、U9C、料号、凭证等 |
| CRM | CRM、客户、销售 |
| 网络 | 网络、网线、VPN、WiFi |
| 设备 | 设备、电脑、打印机、硬件 |
| 打印 | 打印、打印机、打印不了 |
| 其他 | 不匹配以上分类时 |

### 4.4 普通用户指令

#### 提交工单

| 方式 | 说明 |
|------|------|
| `报修 打印机没反应` | 直接描述问题 |
| `提交工单` / `新建工单` / `我有个问题` | 触发创建流程 |

也可以在 AI 回答后反馈：

- AI 回答后会追问「这个回答是否帮到了你？」
- 回复「**是**」→ 满意，归档
- 回复「**否**」→ 不满意，自动创建工单并通知管理员

#### 查看工单

| 指令 | 说明 |
|------|------|
| `我的工单` | 查看自己提交的所有工单 |
| `工单 TKT-20260605-001` | 查看指定工单详情（仅能查看自己的） |

### 4.5 管理员指令

| 指令 | 说明 |
|------|------|
| `待处理` / `工单队列` | 查看所有待处理工单 |
| `工单提醒` | 主动查看待处理工单提醒 |
| `解决 TKT-xxx 解决方案内容` | 标记工单已解决（用户会收到私聊通知） |
| `归档 TKT-xxx` | 归档为运维经验 |
| `无效 TKT-xxx` | 标记为无效工单（不归档为经验） |
| `关闭 TKT-xxx` | 直接关闭工单 |
| `工单统计` | 查看工单统计（支持今日/本周/本月） |
| `日报` | 查看每日工单摘要 |
| `绑定工号 01234567` | 手动设置企业工号（用于私聊通知） |
| `添加工单管理员` | 添加新管理员 |

> 💡 解决工单后系统会追问是否归档为经验，选择「归档」或「无效」即可。

### 4.6 通知机制

| 事件 | 群聊通知 | 私聊通知 |
|------|---------|---------|
| 新工单创建 | ✅ 发到当前群 | ✅ 私聊通知所有管理员 |
| 用户反馈不满意 | ✅ 发到当前群 | ✅ 私聊通知所有管理员 |
| 工单已解决 | — | ✅ 私聊通知工单创建者 |
| 管理员自己创建工单 | ✅ 发到当前群 | 📋 收到副本确认（非完整通知） |

> 📋 **副本确认** vs 🆕 **完整通知**：
> - 副本确认：轻量级，标题「📋 工单副本」，提示"您创建的工单已记录"
> - 完整通知：完整详情，标题「🆕 新工单」/「⚠️ 工单需处理」，提示"请尽快处理"

## 七、常见问题

### Q: 私聊收不到通知？

1. 确认应用已开通「通讯录个人信息读权限」（钉钉开放平台 → 应用 → 权限管理）
2. 开通后 `staff_id` 会自动获取
3. 如果仍未获取，手动发送 `绑定工号 你的工号` 给机器人

### Q: 工单编号为什么重复？

V1.3.5 已修复此问题。此前同一会话内多次反馈"否"会复用同一工单，现在每次都创建独立新工单。

### Q: 专家模式怎么退出？

发送 `退出专家` 或 `取消专家`，或 30 分钟不对话自动退出。

### Q: 工单分类不准？

分类基于关键词匹配。如果分类不准，可以在描述中包含更多关键词（如"U9""网络""打印机"等），系统会据此归类。

### Q: 如何添加新管理员？

发送 `添加工单管理员` 给机器人，或在 `config.yaml` 的 `ticket.admins` 中添加。
