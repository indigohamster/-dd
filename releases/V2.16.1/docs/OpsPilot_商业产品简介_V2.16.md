# OpsPilot 企业智能运维助手

**钉钉里的 AI 运维服务台**

> 让员工在钉钉里解决问题，让运维只处理真正需要人工介入的事情。

OpsPilot 面向使用钉钉的企业 IT 与内部服务团队，将知识问答、智能排障、工单协作、文件处理和运营分析集中到一个入口。系统优先帮助员工自助解决常见问题；无法自动解决的事项会进入可追踪、可处理、可通知、可复盘的工单闭环，并把有效经验持续沉淀为企业知识。

当前产品版本：V2.16.1

## 企业为什么需要 OpsPilot

企业日常运维往往被大量重复咨询和零散报障占据：员工在群聊或私聊中描述问题，运维反复追问信息、手工登记、同步进度，再把处理结果散落在聊天记录和个人经验中。随着人员和系统增加，响应不透明、经验难复用、统计依赖手工的问题会越来越明显。

OpsPilot 将这类工作转化为标准化服务链路：

- **减少重复工作**：知识库优先回答，高频问题先由 AI 分流和辅助排障。
- **规范处理过程**：从受理、分派、处理、解决到员工确认形成完整记录。
- **提升服务透明度**：员工可查询自己的工单，关键状态通过钉钉及时通知。
- **沉淀组织经验**：有效回答和已验收解决方案进入待审核知识候选。
- **统一能力入口**：线上模型、本地模型、IMA 知识库和企业 HTTP 服务可集中配置。

## 核心能力

### 钉钉原生服务入口

员工无需安装新的客户端，可在钉钉群聊或单聊中直接提问、报修、申请服务、上传文件、发送截图或语音，并查询本人事项的处理进度。

### AI 知识问答与智能排障

系统可优先检索 IMA 知识库，再结合大模型组织回答。对于信息不足的问题，会按场景追问必要信息；对于一般故障，可逐步给出安全的排查建议，多次无效后自动转入人工工单。账号权限、数据删除和安全事件等高风险事项可按规则直接转人工。

### 企业工单闭环

支持事件与服务请求、服务目录、优先级、处理组、负责人、首次响应和解决目标、公开回复、内部备注、批量处理与完整时间线。运维标记解决后，员工可以确认恢复并评分，或重新打开仍未解决的工单。

### 知识持续改进

系统记录知识引用、用户反馈与解决效果，把未解决问题、有效的非知识库回答和已验收工单方案整理为待审核候选。管理员补充适用范围、解决步骤和验证方式后，可发布为 Markdown 知识材料并导入 IMA，形成“使用—反馈—审核—沉淀—复用”的闭环。

### 图片、语音和文件处理

支持将报错截图交给兼容的视觉模型分析，也可优先使用钉钉消息自带的语音识别文本；必要时可配置本地 Whisper 作为备用。普通附件可关联到工单，帮助运维保留完整上下文。

### 企业表格助手

支持处理 XLSX、CSV 和 TSV 文件，可完成概览、异常检查、筛选、排序、去重、分类汇总、图表、字段脱敏和双表差异对比。任务在后台执行，不阻塞其他消息，并生成新的结果文件，不覆盖原文件。

### 网络状态诊断

支持检测活动网卡、内网 IP、公网 IP、网关、DNS、解析状态、延迟和丢包，并可按需执行小文件快速测速，帮助员工和运维快速判断常见网络问题。

### 可视化运营操作台

管理端提供首页行动中心、工单、知识、文件与任务、设置五个主要入口，可处理工单、维护服务目录与人员、配置回答方式和模型路由、查看后台任务、通知失败、运行健康、网络状态、数据历史与配置快照。

## 标准服务闭环

1. 员工在钉钉描述问题，或从服务目录提交请求。
2. 系统检索企业知识并进行智能问诊或安全排障。
3. 已解决事项结束服务；未解决事项自动或手动创建工单。
4. 运维在操作台分派、处理、记录内部备注并向员工公开回复。
5. 状态变化通过钉钉通知员工，员工可补充、催办或查询进度。
6. 运维给出解决方案，员工确认恢复并评分；未恢复则重新打开。
7. 已验收方案进入知识候选，经人工审核后沉淀为企业经验。

## 典型应用场景

- 办公网、Wi-Fi、VPN、打印机和终端设备故障。
- 账号解锁、密码重置、系统权限和软件安装申请。
- ERP、CRM 等业务系统异常与使用咨询。
- 新员工入职账号与设备准备、离职权限回收协作。
- 报错截图识别、语音报障和附件留存。
- 日常 Excel 数据清洗、汇总、对比和脱敏。
- 高频问题自助解答与企业知识库持续维护。

## 集成与部署

- 基于钉钉 Stream 与钉钉 OpenAPI，复用企业现有协作入口。
- 支持 DeepSeek、OpenAI 兼容服务、Ollama 和企业内部兼容模型。
- 支持 IMA 知识库、钉钉 AI 表格单向同步，以及自定义 HTTP 连接器的配置与测试；连接器的聊天自动调用需按业务场景进一步集成。
- 提供 Windows EXE、本机可视化管理台和首次配置向导，无需手工编辑 YAML。
- 提供安全配置包迁移，自动移除密钥、认证 Header 和本机绝对路径。
- 支持配置历史、原子写入、任务队列、通知重试和运行状态观测。

## 基础安全设计

- 管理台默认仅监听本机地址，不直接暴露到局域网或公网。
- API Key、Client Secret 和连接器敏感认证值不通过查询接口明文回显。
- 工单管理员使用稳定的钉钉 User ID 或 Staff ID 授权，不按昵称授权。
- 员工只能查询和操作自己的工单，内部备注不会展示给提交人。
- 表格处理不执行宏，任务和临时文件按用户隔离并在完成后清理。
- 配置迁移会生成可追溯快照，服务商或端点变化时不会复用旧密钥。

## 适用客户

OpsPilot 适合以下企业或团队：

- 以钉钉作为主要办公和沟通入口。
- 运维人员有限，但内部咨询、报修和服务申请数量较多。
- 高频问题重复出现，解决经验依赖少数人员。
- 已建设 IMA 知识库，希望增加使用反馈和持续改进链路。
- 需要轻量工单系统，但暂时不希望引入复杂的大型 ITSM 平台。
- 希望接入线上 AI 或本地模型，并保留企业内部系统扩展能力。

## 当前交付范围

OpsPilot V2.16.1 定位为轻量级企业 IT 服务台与智能运维助手，当前采用本机 SQLite，适合单企业的 Windows 本机、企业内网单实例或部门级试点。V2.16.1 统一了机器人与操作台的持久数据路径，修复工单/知识路由冲突，并增加 AI 故障隔离与脱敏持久日志。当前版本不包含完整 CMDB、复杂审批编排、工作日历 SLA、多租户计费和多实例高可用；钉钉 AI 表格为单向同步，知识发布需要人工审核后导入 IMA。标准 EXE 不内置本地 Whisper；表格处理需要额外准备 Node.js 与 `@oai/artifact-tool`。

如需在服务器上开放多人远程管理，正式商用部署应增加生产级应用服务器与反向代理或钉钉免登、统一身份认证、细粒度角色权限、HTTPS、集中密钥管理、企业级数据库、备份恢复和高可用方案。当前配置文件及配置历史未提供静态加密，消息与运行数据也会按配置落盘，应使用操作系统文件权限、访问审计和数据保留策略保护。

数据边界取决于企业选择的服务：使用云模型或 IMA 时，相关问题内容会发送到已配置的外部服务；只有采用本地模型并关闭外部知识服务时，才适合描述为模型数据本地处理。

## 建议落地方式

从一个运维团队、一套知识库和几类高频服务开始试点，先验证自动问答、智能排障、工单闭环和知识沉淀效果；形成稳定流程后，再逐步接入更多服务目录、企业系统与本地模型。

**OpsPilot 不只是回答问题，而是把每一次服务都变成可追踪的过程和可复用的知识。**
