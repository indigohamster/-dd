## 一、系统概述

钉钉 Stream 机器人是日盛集团 IT 运维团队内部使用的智能问答与工单管理工具。通过钉钉 Stream（WebSocket 长连接）协议与企业钉钉实时通信，集成 IMA 知识库和 AI 大模型，提供以下核心能力：

- **智能问答**：基于 IMA 知识库的 RAG 检索增强生成，支持专家模式精准回答
- **IT 工单系统**：完整的工单生命周期管理（创建 → 分配 → 处理 → 解决 → 归档）🆕 V1.4.0 增加优先级判定 + 逾期巡检
- **AI 双引擎**：CodeBuddy + DeepSeek 自动调度，专家模式优先 CodeBuddy
- **语音转文字**🆕：支持语音消息 → Whisper ASR → 文字回复
- **附件管理**🆕：文件/图片自动关联到工单
- **定时任务**🆕：逾期工单巡检 + 每周统计报告

⚠️ **IMA 知识库为词级精确匹配**（非语义搜索），长句子搜不到是预期行为。之前 V1.3.5 操作手册错误描述为"语义搜索"，已在 V1.4.1 手册中更正。

## 二、快速部署

### 2.1 环境要求

| 项目 | 要求 |
|------|------|
| Python | 3.11+ |
| 操作系统 | Windows / Linux / macOS |
| 网络 | 需能访问钉钉 OpenAPI、IMA API、DeepSeek API |
| 可选 🆕 | ffmpeg（语音转文字需要）、Whisper base 模型（~150MB，自动下载） |

### 2.2 安装依赖

```bash
pip install -r requirements.txt
```

核心依赖：`dingtalk-stream`、`openai`（DeepSeek SDK）、`requests`、`pyyaml`

可选依赖 🆕：`openai-whisper`（语音转文字）、`Pillow`（测试图片生成）

### 2.3 配置文件

复制 `config.yaml` 并填写以下必填项：

```yaml
credentials:
  client_id: "你的钉钉 AppKey"         # 即 AppKey
  client_secret: "你的钉钉 AppSecret"   # 即 AppSecret

ima:
  client_id: "IMA 知识库 Client ID"
  api_key: "IMA 知识库 API Key"

llm:
  api_key: "DeepSeek API Key"
  base_url: "https://api.deepseek.com"
  model: "deepseek-chat"

codebuddy:
  enabled: true
  base_url: "http://127.0.0.1:8080"
```

⚠️ **codebuddy.cli_path 配置**：如果自动检测失败，需手动填写 CodeBuddy CLI 路径。V1.1.2 起已增加 fallback 路径检测，但某些环境仍可能找不到。

### 2.4 启动机器人

```bash
python main.py
```

启动后自动执行：
1. 初始化日志、配置、API 客户端
2. 连接 IMA 知识库、DeepSeek LLM、CodeBuddy（如已启用）
3. 自动拉起 CodeBuddy HTTP 服务及 daemon
4. 建立 Stream（WebSocket）长连接
5. 启动逾期工单巡检线程（每 30 分钟）🆕
6. 启动每周统计报告线程（每小时检查，周五 12:00 发送）🆕

⚠️ **V1.4.0 曾出现启动崩溃**：缺少 `import threading` 导致 `NameError`，在 `self.__expert_lock__ = threading.Lock()` 处崩溃。V1.4.1 已修复。如果升级后机器人无法连接钉钉，首先检查控制台日志是否有 `NameError`。

## 三、消息处理流程

### 3.1 主入口逻辑（process）

用户发送消息后，机器人按以下优先级依次处理：

```
收到消息
  ↓
1. 消息解析 & 信息提取（发送者、会话类型、内容）
  ↓
2. 会话类型开关检查（enable_p2p / enable_group）
  ↓
3. 关键词过滤（keyword_filter 配置）
  ↓
4. 非文本消息 → _handle_file_message()  🆕 整个非文本消息处理分支为 V1.4.0 新增
   ├─ 语音 → Whisper 转文字 → 重新进入文本处理  🆕
   └─ 文件/图片 → 下载 + 关联工单  🆕
  ↓
5. 专家召唤触发词 → 设置专家状态 + 处理召唤
  ↓
6. 旧触发词（"搜"/"查"/"找"）→ 返回原始知识库搜索结果
  ↓
7. 文件发送测试指令（"测试文件"等）
  ↓
8. AI 引擎切换指令（"切换CodeBuddy"/"切换DeepSeek"等）
  ↓
9. 专家模式意图检测（退出/切换/列表）
  ↓
10. 反馈回复检测（"是"/"否"）
  ↓
11. 工单系统指令解析
  ↓
12. 普通消息 → AI 对话（知识库搜索 + LLM 生成）
```

⚠️ **语音转文字的递归问题**：`_handle_voice_message` 调用 `_process_text_message` 而非递归调用 `process`。`_process_text_message` 是 `process` 中文本处理逻辑的简化版，**不包含**反馈检测、工单系统、AI 引擎切换等逻辑，只走：专家召唤 → 旧触发词 → AI 对话。这意味着语音识别后的文字**不会触发工单指令和反馈检测**。

### 3.2 非文本消息处理 🆕

#### 语音消息

1. 通过钉钉 API 下载语音文件
2. 使用 Whisper ASR 转文字（支持 AMR/MP3/WAV，自动 ffmpeg 转换）
3. 识别结果作为普通文本消息继续处理
4. 语音识别功能需安装 `openai-whisper`，首次使用自动下载 base 模型（~150MB）

⚠️ **Whisper 模型下载**：首次使用时会自动下载 base 模型到用户目录，约 150MB。如果网络受限，可能下载失败。此时语音转文字功能不可用，但机器人仍可正常处理文本消息。

⚠️ **ffmpeg 依赖**：Whisper 依赖 ffmpeg 做音频格式转换（钉钉语音默认为 AMR 格式）。如果未安装 ffmpeg，只有 WAV 格式可以处理。

#### 文件/图片消息

1. 下载文件到 `data/attachments/`
2. 重新上传获取 `media_id`
3. 查找发送者 1 小时内的待处理工单
4. 有工单 → 关联附件到工单 description 字段
5. 无工单 → 暂存附件信息，等待用户发送文字后自动创建工单

⚠️ **附件暂存机制缺陷**：`_pending_attachments` 是普通 dict，没有过期清理。如果用户发送文件后一直不发文字，暂存数据会一直留在内存中。重启后也会丢失。

⚠️ **附件关联方式**：附件信息是追加到工单的 `description` 字段文本中，而非独立存储。多次关联会导致 description 越来越长，没有结构化附件列表。

## 四、AI 引擎调度

### 4.1 双引擎架构

| 引擎 | 用途 | 调度规则 |
|------|------|---------|
| **CodeBuddy Code** | 专家模式首选 | 专家模式 → CodeBuddy 优先，失败降级 DeepSeek |
| **DeepSeek** | 普通模式首选 | 普通模式 → DeepSeek 优先，失败不降级 |

🆕 **V1.4.0 异常保护**：AI 引擎调用现已包裹在 try-except 中，捕获 `DeepSeekAPIError` 和通用 `Exception`。之前版本如果 DeepSeek 返回错误（如 429 限流），错误字符串会直接暴露给用户。

### 4.2 手动切换指令

| 指令 | 效果 |
|------|------|
| `切换CodeBuddy` / `切换CB` / `用CodeBuddy` / `用cb` | 强制使用 CodeBuddy |
| `切换DeepSeek` / `切换DS` / `用DeepSeek` / `用ds` | 强制使用 DeepSeek |
| `自动调度` / `恢复自动` / `自动引擎` | 恢复自动调度规则 |
| `当前引擎` / `什么引擎` / `用的什么AI` | 查看当前引擎状态 |

### 4.3 CodeBuddy 配置

CodeBuddy 需要本地启动 HTTP 服务，机器人会自动拉起：

```yaml
codebuddy:
  enabled: true
  base_url: "http://127.0.0.1:8080"
  auto_start: true
  cli_path: ""           # 自动检测
  custom_model: "custom-local:deepseek-chat"
```

⚠️ **CodeBuddy 自动启动**：自动拉起依赖 `codebuddy` CLI 在 PATH 中或 `cli_path` 配置正确。在某些环境中自动检测可能失败，需手动配置路径。

⚠️ **429 限流**：CodeBuddy 云端 API 有调用频率限制。配置 `custom_model: "custom-local:deepseek-chat"` 可绕过，使用本地 DeepSeek 模型替代。

## 五、专家模式

### 5.1 工作流程

```
用户: 召唤U9专家 料号怎么修改
  ↓
机器人: 🦊 召唤U9专家⚡ 已就位！
         后续的问题我都会基于这位专家的知识库来回答哦～
  ↓
（同时）搜索 U9 知识库 "料号怎么修改"
  ↓
合并搜索结果 → 构建 Prompt → CodeBuddy/DeepSeek 生成回答
  ↓
机器人: [基于U9知识库的回答]
         ---
         💡 当前由 **召唤U9专家** 为您服务
```

### 5.2 专家状态管理

| 操作 | 方式 |
|------|------|
| **激活** | 发送 `召唤XX专家`（可附带问题） |
| **切换** | 发送另一个 `召唤XX专家` |
| **退出** | 发送 `退出专家模式` / `退出专家` / `取消专家` |
| **列表** | 发送 `专家列表` / `有哪些专家` |
| **过期** | 30 分钟无对话自动清除 |

🆕 **V1.4.0 线程安全**：`_expert_states` 字典操作现已用 `threading.Lock` 保护。之前版本在多线程并发时可能出现竞态条件。

### 5.3 当前已配置专家

| 触发词 | 搜索范围 | 说明 |
|--------|---------|------|
| `召唤运维专家` | 全部默认知识库 | 综合运维问题 |
| `召唤U9专家` | 仅 U9 问题处理知识库 | U9 系统专项 |
| `召唤售后专家` | 仅日盛售后服务知识库 | 售后业务专项 |

⚠️ **专家搜索范围**：实际搜索范围取决于 `config.yaml` 中 `expert_triggers` 的 `target_kbs` 配置。如果 `target_kbs` 为空或配置了错误的 KB ID，专家模式可能搜不到结果。

### 5.4 专家模式 AI 调度

专家模式下，AI 引擎自动切换为 **CodeBuddy 优先**：
- CodeBuddy 可用 → 使用 CodeBuddy 生成回答
- CodeBuddy 不可用/失败 → 自动降级到 DeepSeek

🆕 **V1.4.0 异常保护**：降级逻辑现已包裹在 try-except 中，捕获 `DeepSeekAPIError`。之前如果 CodeBuddy 返回 None 且 DeepSeek 也出错，用户会看到原始错误信息。

## 六、知识库搜索策略

IMA 知识库使用 **词级精确匹配**（非语义搜索），机器人内置多层搜索策略：

⚠️ **重要更正**：V1.3.5 操作手册将 IMA 搜索描述为"语义搜索"，这是**错误的**。IMA `search_knowledge` API 是词级精确匹配：
- "U9" → 67条
- "U9操作" → 3条
- "U9怎么用啊" → 0条

长句子搜不到是预期行为，不是 bug。

### 6.1 搜索流程

```
用户提问: "U9料号怎么修改啊"
  ↓
策略1: 完整query搜索 → "U9料号怎么修改啊" → 可能0条
  ↓ 无结果
策略2: 关键词拆分搜索
  ├─ 领域词表整词匹配: "料号修改" ✅
  ├─ 英文/数字词: "U9" ✅
  └─ 中文滑动窗口切词: "怎么" "修改" "啊" (过滤停用词)
  ↓
合并去重所有结果 → 返回前 N 条（默认5条，专家模式8条）
```

### 6.2 领域词表

内置 101 个 IT 运维领域复合词（`DOMAIN_TERMS`），优先级高于滑动窗口切词，防止 `料号修改` 被切成无意义碎片。

覆盖范围：U9C/ERP、系统账号/权限、网络/硬件、软件/工具、常见问题类型、NAS/服务器。

### 6.3 质量过滤

- 过滤摘要内容 < 30 字的低质量结果（防止噪音干扰 AI）
- 若所有结果都低质量，保留全部（总比没有强）

### 6.4 回答格式约束（有知识库结果时）

- 操作步骤 **必须用编号列表**（1. 2. 3.）
- 回答末尾 **必须标注来源**（如 `[来源: U9问题处理知识库]`）
- **禁止补充**知识库未提及的信息
- 字数上限 800 字

## 七、IT 工单系统

### 7.1 工单生命周期

```
创建(open) → 分配(assigned) → 处理中(in_progress) → 已解决(resolved) → 已关闭(closed)
                                                                    ↓
                                                        归档为经验 / 标记为无效
```

### 7.2 工单优先级 🆕

| 优先级 | 标签 | 逾期阈值 |
|--------|------|---------|
| urgent | 🔴 紧急 | 2 小时 |
| high | 🟠 高 | 8 小时 |
| medium | 🟡 中 | 24 小时 |
| low | 🟢 低 | 72 小时 |

优先级判定方式：
1. **关键词快路径**：消息包含"紧急"/"urgent"等关键词 → 直接判定
2. **AI 判定**：调用 DeepSeek 分析内容 → 返回优先级
3. **默认**：medium

⚠️ **AI 优先级判定的额外 API 开销**：当关键词快路径不命中时，会额外调用一次 DeepSeek API 来判定优先级。这在 DeepSeek API 限流或延迟高时，会拖慢工单创建速度。

⚠️ **AI 判定结果的不确定性**：DeepSeek 对同一内容可能返回不同优先级。关键词快路径是确定性的，建议尽量通过关键词覆盖常见场景。

❌ **相似工单推荐**：V1.4.0 计划中包含"相似工单推荐"功能（创建工单时推荐已解决的类似工单），代码中已有 `search_similar_tickets()` 方法，但 **在工单创建流程中并未实际调用**。该功能处于"代码就绪但未接入"状态。

### 7.3 工单分类

| 分类 | 说明 |
|------|------|
| U9问题 | U9/ERP 相关 |
| CRM问题 | 客户关系管理 |
| 网络问题 | 网络/VPN/远程 |
| 设备问题 | 硬件/打印机 |
| 账号问题 | 域账号/权限 |
| 其他 | 未匹配以上分类 |

分类判定：IMA 知识库 KB ID 匹配 → KB 名称关键词匹配 → 内容关键词兜底

### 7.4 用户指令

| 指令 | 说明 |
|------|------|
| `报修 U9登录不了` | 创建工单（标题自动取内容） |
| `我的工单` | 查看我的工单列表 |
| `工单详情 TKT-20260608-001` | 查看工单详情 |

### 7.5 管理员指令

| 指令 | 说明 |
|------|------|
| `工单列表` | 查看所有工单 |
| `待处理工单` | 查看待处理工单 |
| `分配工单 TKT-xxx @张三` | 分配工单给某人 |
| `处理工单 TKT-xxx 修复方案说明` | 标记工单为处理中 |
| `解决工单 TKT-xxx 解决方案说明` | 解决工单 |
| `关闭工单 TKT-xxx` | 关闭工单 |
| `工单统计` | 查看统计数据 |
| `添加管理员 @用户` | 添加管理员 |
| `归档经验 TKT-xxx` | 将工单归档为经验 |
| `标记无效 TKT-xxx` | 标记为无效工单 |

### 7.6 通知机制

- **新工单**：通知管理员（群聊 + 私聊），创建者收到副本确认
- **不满意反馈**：工单升级为"处理中"，通知管理员
- **工单解决**：通知创建者（私聊），解决者本人不重复通知
- **逾期巡检** 🆕：每 30 分钟检查，按优先级阈值判定逾期，通知管理员

⚠️ **私聊通知的 staff_id 依赖**：私聊通知优先使用 `staff_id`（企业userId），如果管理员/创建者缺少 `staff_id`，会降级使用 `openId`，但钉钉 `oToMessages/batchSend` 接口需要 `staffId`，降级后大概率失败。代码中已有 warning 日志提示。

### 7.7 数据存储

工单数据存储在 `data/tickets.db`（SQLite），启用 WAL 模式，线程安全。首次管理员自动添加（管理员表为空时，第一个交互用户自动成为管理员）。

## 八、AI 回答反馈闭环

### 8.1 反馈流程

```
AI 回答后追加提示: "以上回答是否帮助到您？回复 是 / 否"
  ↓
用户回复"是" → 工单标记解决，记录满意度
用户回复"否" → 工单升级为"处理中"，通知管理员介入
```

### 8.2 反馈有效期

仅在 AI 回答后有 pending 状态时生效，同一会话只保留最近一次反馈等待。

⚠️ **反馈状态非线程安全**：`_pending_feedback` 字典没有加锁保护。虽然实际场景中并发冲突概率很低（同一会话同时只有一条待反馈），但严格来说存在竞态条件。

## 九、定时任务 🆕

### 9.1 逾期工单巡检 🆕

| 配置项 | 值 |
|--------|-----|
| 检查频率 | 每 30 分钟 |
| 判定规则 | 创建时间 + 优先级阈值 < 当前时间 |
| 通知方式 | 私聊管理员 |
| 阈值 | urgent=2h, high=8h, medium=24h, low=72h |

⚠️ **巡检线程为 daemon 线程**：主进程退出时巡检线程会自动终止，不会阻止程序退出。但也意味着如果主进程异常退出，巡检不会继续运行。

### 9.2 每周统计报告 🆕

| 配置项 | 值 |
|--------|-----|
| 检查频率 | 每小时 |
| 发送时间 | 每周五 12:00 |
| 发送对象 | `weekly_report.recipients` 配置的用户列表 |
| 内容 | 本周新建/解决/待处理/逾期工单数、分类统计、平均解决时间 |

## 十五、故障排查

### 15.1 机器人无响应

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| 完全无响应 | Stream 连接未建立 | 检查 `client_id` / `client_secret` 是否正确；查看控制台日志 |
| 启动即崩溃 🆕⚠️ | `import threading` 缺失（V1.4.0→V1.4.1 已修复） | 确认版本为 V1.4.1+ |
| @机器人无反应 | 群聊开关关闭 | 确认 `chat.enable_group: true` |
| 单聊无反应 | 单聊开关关闭 | 确认 `chat.enable_p2p: true` |
| 启动即退出 | 凭证错误 | 检查钉钉开放平台凭证是否有效 |

⚠️ **V1.4.0 的致命 Bug**：`chat_handler.py` 缺少 `import threading`，在 `__init__` 中创建 `self.__expert_lock__ = threading.Lock()` 时抛出 `NameError`，导致整个 bot 在 Stream 连接建立前就崩溃了。V1.4.1 已修复。**升级时务必确认版本号**。

### 15.2 AI 回答异常

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| 回答为原始 JSON | CodeBuddy 解析失败 | 已内置 `_sanitize_answer` 清洗，若仍出现请查看日志 |
| 回答超时（>30s） | CodeBuddy 429 限流 | 配置自定义 DeepSeek 模型（见 CodeBuddy 配置） |
| 知识库搜不到 | IMA 凭证错误或关键词不匹配 | 检查 `ima.client_id` / `ima.api_key`；尝试更短的关键词 |
| DeepSeekAPIError 🆕 | API 限流/超时/认证失败 | 检查 API Key 和余额；V1.4.0+ 已内置异常捕获 |
| 回答内容不相关 | 知识库无相关内容 | 正常，AI 会使用通用知识回答，并注明来源 |

🆕 **V1.4.0 DeepSeekAPIError**：`deepseek_client.py` 将所有错误从返回字符串改为抛出 `DeepSeekAPIError` 异常（含 `status_code` 属性）。`chat_handler.py` 中 AI 引擎调用现已用 try-except 包裹。如果其他地方也调用了 `llm_client.chat()` 但没有 catch，会抛出未捕获异常。

### 15.3 CodeBuddy 连接失败

| 现象 | 解决方案 |
|------|---------|
| `CodeBuddy AI 连接测试失败` | 确认 CodeBuddy HTTP 服务已启动（`codebuddy --serve --port 8080`） |
| `CodeBuddy daemon 未运行` | 机器人会自动拉起，若失败手动执行：`curl -X POST http://127.0.0.1:8080/api/v1/daemon/start` |
| 429 限流错误 | 在 CodeBuddy UI 中配置自定义 DeepSeek 模型，绕过云端限流 |

### 15.4 文件发送失败

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| `文件发送功能未启用` | 钉钉凭证未配置 | 确认 `credentials` 段填写完整 |
| `无法获取用户user_id` | 单聊场景权限不足 | 需要钉钉管理员开通 `Contact.User.Read` 权限 |
| 发送后无反应 | media_id 获取失败 | 检查 `dingtalk_api.py` 中 `upload_file` 的返回 |

### 15.5 语音转文字失败 🆕

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| `语音识别功能暂未启用` | 未安装 whisper | `pip install openai-whisper` |
| `ffmpeg not found` | 未安装 ffmpeg | 安装 ffmpeg 并加入 PATH |
| 识别结果为空 | 语音过短或噪音过大 | 提示用户用文字描述 |

⚠️ **语音转文字端到端未验证**：此功能在开发环境中已编码完成，但完整的钉钉语音消息 → 转文字 → AI 回复流程未经实际测试。

### 15.6 access_token 获取失败 🆕

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| 频繁 token 失效 | 并发获取 token 导致竞态 | V1.4.0+ 已内置双检锁 + 2 次重试 |
| token 持续获取失败 | AppKey/AppSecret 错误 | 检查凭证配置 |

🆕 **V1.4.0 `get_access_token` 增强**：
- 双检锁模式（double-check locking）防止并发重复获取
- 2 次重试 + 指数退避（1s, 2s）
- token 过期后自动刷新

## 十七、常见问题 FAQ

**Q：如何让机器人只回复特定关键词的消息？**
A：在 `config.yaml` 中设置 `chat.keyword_filter: ["关键词1", "关键词2"]`，为空则不过滤。

**Q：专家模式能同时激活多个吗？**
A：不能，每个会话同时只能激活一个专家。发送新的召唤词会切换。

**Q：DeepSeek API Key 泄露了怎么办？**
A：登录 https://platform.deepseek.com 进入 API Keys 页面删除旧 Key，重新生成。

**Q：如何更新机器人代码？**
A：拉取最新代码 → 确认 `config.yaml` 配置 → 重启（`quit` 然后重新 `python main.py`）。

**Q：机器人可以作为 Windows 服务运行吗？**
A：当前版本不支持，需在控制台窗口运行。可使用 `nssm` 或 `pywin32` 自行封装为服务。

**Q：IMA 知识库搜不到结果怎么办？** ⚠️ 更正
A：IMA 是词级精确匹配（非语义搜索），长句子搜不到是正常的。尝试缩短关键词，如用"料号修改"替代"U9料号怎么修改啊"。**旧版手册错误描述为语义搜索**。

**Q：工单优先级是怎么判定的？** 🆕
A：先检查关键词（"紧急"→urgent），再调用 AI 判定，最后默认 medium。

**Q：为什么语音转文字不生效？** 🆕
A：需要安装 `openai-whisper` 和 `ffmpeg`，首次使用会自动下载模型。检查控制台日志是否有相关错误。

**Q：access_token 获取失败怎么办？** 🆕
A：V1.4.0+ 已内置双检锁 + 2 次重试机制（指数退避 1s/2s）。如仍失败，检查 AppKey/AppSecret 是否正确。

**Q：升级到 V1.4.0 后机器人无法连接钉钉怎么办？** ⚠️
A：这是 V1.4.0 的已知 Bug（缺少 `import threading`）。请确认已升级到 V1.4.1，检查控制台日志是否有 `NameError: name 'threading' is not defined`。
