## V2.6 企业文件助手

第一阶段支持 `.xlsx`、`.csv` 和 `.tsv`。在钉钉中先发送表格文件，再发送处理指令：

- `表格概览`
- `检查异常`
- `去重` 或 `按客户列去重`
- `筛选状态为未完成`
- `按部门汇总金额`
- `取消表格处理`

机器人会生成新的 Excel 文件并发回，原文件不会被覆盖。概览和异常检查会生成“处理报告”；筛选、去重和汇总会创建对应结果工作表。

管理后台“文件助手”页面可以设置最大文件大小、处理超时及运行环境。当前依赖 Node.js 和 `@oai/artifact-tool`，本机已配置工作区运行库；迁移服务器后需要在该页面更新路径。

安全限制：默认最大 20MB；仅处理表格数据，不执行宏；任务按群成员隔离；完成后清理本地临时输入和输出。

## V2.5 图片识别与每日驾驶舱

### 图片报错识别

在管理后台“多模型路由”中添加一个支持 OpenAI 兼容图片消息的视觉模型，并在“图片理解”中选择该模型。员工向机器人发送报错截图后，机器人会提取系统/窗口、错误码、关键报错、初步判断和仍需补充的信息，再进入正常排障流程。

如果未配置图片模型、图片超过 10MB或模型调用失败，机器人会保留原有行为：接收图片并关联最近工单或暂存到下一张工单，不影响报修。

### 每日运维驾驶舱

打开管理后台左侧“每日驾驶舱”，可查看今日新增与解决、当前待办、逾期、高优先级、平均解决耗时、重复故障、知识缺口和低效知识来源。建议每天早上和下班前各查看一次。

## V2.3 知识闭环

管理后台新增“知识闭环”页面。系统会记录 IMA 知识引用与用户反馈，把未解决问题放入待改进池，并将有效的非知识库回答、已解决工单整理为待审核知识候选。

推荐工作流：查看待审核候选 → 补充适用范围、解决步骤、验证方式和无效时处理 → 审核通过 → 发布。发布后会在 `data/knowledge_exports/` 生成 Markdown 文件，确认内容后可导入 IMA。直接写入 IMA 需要后续接入具备写权限的正式接口。

```yaml
knowledge_loop:

  export_dir: "data/knowledge_exports"
  publish_mode: "markdown_export"
```

## 一、项目简介

**运维数字人** 是一个基于钉钉 Stream 协议的智能运维助手，支持：

- 📚 **知识库问答** — 对接 IMA 知识库，搜索 U9、售后、软硬件维护等资料
- 🤖 **AI 智能回答** — DeepSeek / CodeBuddy 双引擎，自动调度
- 🔧 **专家模式** — 召唤专属专家，限定知识库范围，30分钟会话记忆
- 📎 **富媒体发送** — 支持向群聊/单聊发送文件、图片
- 📊 **后台仪表盘** — 运行时状态、API 统计、引擎监控

### 3.5 内置工单数据库

工单系统使用内置 SQLite，无需部署 MySQL。默认数据库为 `data/tickets.db`：

```yaml
ticket:
  enabled: true
  database_path: "data/tickets.db"
  integrity_check: true
  busy_timeout_ms: 5000
  backup_enabled: true
  backup_dir: "data/backups"
  backup_retention_days: 30
```

- 相对路径以项目根目录为基准，也可以配置绝对路径。
- 启动时自动建表、迁移 Schema 并执行完整性检查。
- 每天首次启动会生成 `tickets-YYYYMMDD.db` 一致性备份；同一天不会重复创建。
- 超过保留天数的备份会自动清理，默认保留 30 天。
- 数据库损坏时机器人拒绝启动。应保留损坏文件，并从最近备份复制恢复，避免覆盖证据。
- 单实例运行时使用 SQLite；需要多实例同时写入时应迁移到 MySQL 或 PostgreSQL。

### 3.6 消息开关配置

```yaml
chat:
  auto_echo: false   # 调试用，true = 机器人原样回显消息
  enable_p2p: true   # 是否响应单聊消息
  enable_group: true  # 是否响应群聊 @机器人 消息
  keyword_filter: []  # 为空 = 不过滤；填入关键词则只响应含关键词的消息
```

## 五、群聊/单聊指令大全

在钉钉群聊中 **@机器人** 或单聊中直接发送以下指令：

### 5.1 专家模式（推荐）

| 指令格式 | 功能说明 |
|---------|---------|
| `召唤运维专家` | 激活运维专家，搜全部默认知识库 |
| `召唤运维专家 怎么改U9密码` | 激活专家并直接回答 |
| `召唤U9专家` | 激活U9专家，仅搜U9知识库 |
| `召唤U9专家 料号怎么修改` | 激活U9专家并直接回答 |
| `召唤售后专家` | 激活售后专家，仅搜售后知识库 |

> 💡 召唤专家后，后续 **30分钟内** 的对话自动沿用该专家的知识库范围。
> 发送新召唤词会切换专家；30分钟无对话自动退出专家模式。

### 5.2 知识库搜索（原始结果）

| 指令格式 | 功能说明 |
|---------|---------|
| `搜 XXX` | 搜索知识库，返回原始结果列表 |
| `查 XXX` | 同上 |
| `找 XXX` | 同上 |

### 5.3 AI 引擎切换

| 指令 | 功能说明 |
|------|---------|
| `切换CodeBuddy`（或 `切换CB`/`用CodeBuddy`） | 手动锁定使用 CodeBuddy 引擎 |
| `切换DeepSeek`（或 `切换DS`/`用DeepSeek`） | 手动锁定使用 DeepSeek 引擎 |
| `自动调度`（或 `恢复自动`/`自动引擎`） | 恢复智能调度（默认） |
| `当前引擎`（或 `什么引擎`/`用的什么AI`） | 查看当前引擎状态和调度规则 |

> 引擎锁定仅对当前群聊或当前单聊生效，不会影响其他会话；30 分钟无交互后自动恢复自动调度。

### 5.4 工单系统

| 指令 | 功能说明 |
|------|---------|
| `报修` / `提交工单` / 描述故障 | 创建工单（自动分类 + 通知管理员） |
| `我的工单` | 查看我提交的工单列表 |
| `工单 TKT-xxx` / `#TKT-xxx` | 查看工单详情 + 操作日志 |
| `待处理` / `工单队列` | **管理员**：查看所有待处理工单 |
| `解决 TKT-xxx 解决方案` | **管理员**：标记工单已解决，用户自动收到通知 |
| `关闭 TKT-xxx` | 关闭工单（创建者或管理员） |
| `工单统计` / `今日工单` / `周统计` | 查看工单统计 |
| `日报` / `每日工单` / `工单日报` | 查看每日工单摘要 |

> 💡 工单创建后管理员会自动收到群聊+私聊通知；管理员解决工单后用户会自动收到私聊反馈。

#### 自动问诊

当报修描述少于配置的完整度阈值时，机器人不会立即把模糊问题推给管理员，而是依次询问：

1. 涉及的系统/设备、操作步骤和完整错误信息；
2. 开始时间、是否重启以及已经尝试的处理；
3. 影响人数、业务范围和是否完全阻断工作。

回复 `取消报修` 可取消；初始描述已经完整时加入 `直接提交` 可跳过问诊。

#### 重复报障与群体故障

机器人会在配置的时间窗口内比较同分类活跃工单。命中相似问题时通知用户和管理员；存在两条以上相似工单时标记为“疑似群体故障”，便于统一处理。

#### 解决效果回访与重开

管理员解决工单后，机器人默认在 24 小时后私聊用户确认。问题仍未解决时回复：

```text
重开 TKT-20260715-001
```

工单会重新进入“处理中”并通知管理员。只有工单创建者和管理员可以重开。

#### 每日个人运维摘要

每天默认 09:00 向已绑定 `staff_id` 的管理员发送一份摘要，内容包括待处理、高优先级、逾期、等待用户确认、今日新建和今日解决数量。

### 5.5 其他指令

| 指令 | 功能说明 |
|------|---------|
| `测试文件` / `发个测试文件` | 测试文件发送功能（发送测试txt+图片） |
| 直接发送消息（无指令前缀） | 走 AI 智能回答（先搜知识库，再 AI 生成回答） |

### 5.6 文件、图片和语音

- 文件和图片会关联到用户一小时内最近的待处理工单；没有工单时暂存一小时，等待用户发送文字描述。
- 暂存附件每 5 分钟清理一次，关联成功、被新附件替换或过期后删除本地临时文件。
- 文件名会由机器人安全净化并使用随机落盘名，原始目录信息不会被采用。
- 语音需要钉钉 OpenAPI、Whisper 和 ffmpeg；任一能力未配置时会提示改用文字。
- 钉钉消息类型同时兼容 `audio` 和 `voice`。如果消息自带识别文本，机器人会直接处理；否则使用本地 Whisper 转写。
- 钉钉 OpenAPI 未初始化时，文件、图片和语音不会尝试下载。

### 5.7 新会话欢迎引导

首次对话时，机器人会自动发送使用引导，包含：
- 直接提问说明
- 知识库搜索指令
- 召唤专家指令列表

## 可视化管理后台（V2.0.0）

运行 EXE 后会自动打开浏览器管理页面：

```text
http://127.0.0.1:8765
```

后台只监听本机地址，不提供登录页，其他电脑无法直接访问。可在 `config.yaml` 中调整：

```yaml
admin_ui:
  enabled: true
  port: 8765
  auto_open: true
```

管理后台包含以下页面：

- **总览**：查看机器人、钉钉、知识库和 LLM 的运行状态。
- **AI API**：修改 OpenAI 兼容 API、模型和参数，并测试连接。
- **连接器**：管理钉钉、IMA 和企业 HTTP 服务。
- **人员**：维护姓名、Staff ID、部门、职责和擅长领域。
- **回答策略**：设置助手身份、语气、长度、知识来源和转人工规则。
- **工单工作台**：查看工单时间线，进行分派、处理、解决和关闭。
- **多模型路由**：为普通问答、工单分析、图片理解设置首选及备用模型。
- **配置历史**：查看自动快照并将配置回滚到历史版本。

AI API 修改保存在 `config.yaml`；连接器、人员和回答策略保存在 `data/admin_settings.json`。API Key 在页面中不会回显明文。

HTTP 连接器支持 `{{input}}` 等变量。例如：

```text
URL: https://cmdb.example/api/server/{{server}}
请求体: {"query":"{{input}}"}
响应映射:
状态=data.status
磁盘=data.disk.percent
```

配置历史保存在 `data/config_history/`。快照可能包含服务密钥，应与主程序配置采用相同的文件访问保护措施。

### 智能问题处置（V2.2.0）

用户可以直接自然描述问题。机器人会判断问题类型，并只询问缺失的关键信息：

```text
用户：财务部 HP 1020 打印机今天早上脱机，重启无效，三个人不能打印
机器人：信息已经足够，直接提供第一步安全处理方案
用户：还是不行
机器人：记录第一步无效，提供不同的第二步方案
用户：没变化
机器人：自动创建工单，并附带全部排查记录
```

支持的反馈包括：

- `好了`、`恢复了`、`正常了`：结束处理。
- `还是不行`、`没变化`、`看不到这个选项`：进入下一种方案。
- `转人工`、`直接报修`：立即创建人工工单。
- `取消处理`：结束当前排障会话。

安全事件、权限申请、密码重置和账号解锁会直接转人工，不执行普通自助操作。

```yaml
problem_resolution:
  enabled: true
  max_failures_before_ticket: 2
  ttl_seconds: 1800
```

## 七、AI 引擎调度规则

机器人内置 **智能调度策略**，也可手动覆盖：

### 自动调度规则

| 场景 | 首选引擎 | 降级策略 |
|------|---------|---------|
| 专家模式（召唤专家后） | CodeBuddy Code | 失败 → 降级 DeepSeek |
| 普通对话（同时配置两种引擎） | DeepSeek | 失败 → 不降级 |
| 普通对话（仅配置 CodeBuddy） | CodeBuddy Code | 直接使用 CodeBuddy |

### 手动切换

发送 `切换CodeBuddy` / `切换DeepSeek` 可在当前会话手动锁定引擎；
发送 `自动调度` 恢复智能调度。锁定状态 30 分钟无交互自动过期。

### 引擎状态查看

发送 `当前引擎` 查看：
- 当前调度模式（自动/手动锁定）
- DeepSeek / CodeBuddy 可用状态
- 自动调度规则说明


## 九、知识库搜索策略

IMA 知识库使用 **词级精确匹配**（非语义搜索），机器人内置了多层搜索策略：

### 搜索流程

```
用户提问: "U9料号怎么修改啊"
  ↓
策略1: 完整query搜索 → "U9料号怎么修改啊" → 可能0条
  ↓ 无结果
策略2: 关键词拆分搜索
  ├─ 整词匹配领域词表: "料号修改" ✅
  ├─ 英文/数字词: "U9" ✅
  └─ 中文滑动窗口切词: "怎么" "修改" "啊" (过滤停用词)
  ↓
合并去重所有结果 → 返回前 N 条（默认5条，专家模式8条）
```

### 质量过滤

- 过滤摘要内容 < 30字 的低质量结果（防止噪音干扰 AI）
- 若所有结果都低质量，保留全部（总比没有强）

### 回答格式约束（有知识库结果时）

- 操作步骤 **必须用编号列表**（1. 2. 3.）
- 回答末尾 **必须标注来源**（如 `[来源: U9问题处理知识库]`）
- **禁止补充**知识库未提及的信息
- 字数上限 800 字

## 十一、文件/图片发送功能

机器人支持向 **群聊** 和 **单聊** 发送文件/图片。

机器人会发送：
- 一个测试文本文件（`测试文件.txt`）
- 一张测试图片（`测试图片.png`）

## 十二、故障排查

### 12.1 机器人无响应

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| 完全无响应 | Stream 连接未建立 | 检查 `client_id` / `client_secret` 是否正确；查看控制台日志 |
| @机器人无反应 | 群聊开关关闭 | 确认 `chat.enable_group: true` |
| 单聊无反应 | 单聊开关关闭 | 确认 `chat.enable_p2p: true` |
| 启动即退出 | 凭证错误 | 检查钉钉开放平台凭证是否有效 |

### 12.2 AI 回答异常

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| 回答为原始 JSON | CodeBuddy 解析失败 | 已内置 `_sanitize_answer` 清洗，若仍出现请查看日志 |
| 回答超时（>30s） | CodeBuddy 429 限流 | 配置自定义 DeepSeek 模型（见 3.4 节） |
| 知识库搜不到 | IMA 凭证错误 | 检查 `ima.client_id` / `ima.api_key` |
| 回答内容不相关 | 知识库无相关内容 | 正常，AI 会使用通用知识回答，并注明来源 |

### 12.3 CodeBuddy 连接失败

| 现象 | 解决方案 |
|------|---------|
| `CodeBuddy AI 连接测试失败` | 确认 CodeBuddy HTTP 服务已启动（`codebuddy --serve --port 8080`） |
| `CodeBuddy daemon 未运行` | 机器人会自动拉起，若失败手动执行：`curl -X POST http://127.0.0.1:8080/api/v1/daemon/start` |
| 429 限流错误 | 在 CodeBuddy UI 中配置自定义 DeepSeek 模型，绕过云端限流 |

### 12.4 文件发送失败

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| `文件发送功能未启用` | 钉钉凭证未配置 | 确认 `credentials` 段填写完整 |
| `无法获取用户user_id` | 单聊场景权限不足 | 需要钉钉管理员开通 `Contact.User.Read` 权限 |
| 发送后无反应 | media_id 获取失败 | 检查 `dingtalk_api.py` 中 `upload_file` 的返回 |

## 十五、常见问题 FAQ

**Q：如何让机器人只回复特定关键词的消息？**
A：在 `config.yaml` 中设置 `chat.keyword_filter: ["关键词1", "关键词2"]`，为空则不过滤。

**Q：专家模式能同时激活多个吗？**
A：不能，每个会话同时只能激活一个专家。发送新的召唤词会切换。

**Q：DeepSeek API Key 泄露了怎么办？**
A：登录 https://platform.deepseek.com 进入 API Keys 页面删除旧 Key，重新生成。

**Q：如何更新机器人代码？**
A：拉取最新代码 → 确认 `config.yaml` 配置 → 重启（`quit` 然后重新 `python main.py`）。

**Q：机器人可以作为 Windows 服务运行吗？**
A：当前版本不支持，需在控制台窗口运行。可使用 `nssm` 或 `pywin32` 自行封装为服务。
