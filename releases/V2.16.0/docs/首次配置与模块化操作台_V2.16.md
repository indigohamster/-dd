# V2.16 首次配置与模块化操作台

## 目标

V2.16 将交付方式从“修改配置文件后启动”改为“空白包先启动，再由页面完成配置”。零配置指不需要手工编辑 YAML、JSON、可执行文件路径或并发参数；钉钉和云模型提供商要求的授权信息仍须由企业管理员填写。

管理台仅绑定 `127.0.0.1`，没有新增登录页面。未来部署到公司服务器并允许远程访问时，仍需在反向代理或钉钉免登层增加真实身份和权限控制。

## 全新环境首次启动

1. 将整个 `dist/dingtalk-ops-v2.16.0-package/` 目录复制到本机可写位置；不要在压缩包、`Program Files` 或只读共享盘内运行，并确保 8765 端口可用。
2. 启动 EXE。凭证不完整时机器人不会连接 Stream，但本机管理台会正常启动。
3. 浏览器打开 `http://127.0.0.1:8765`，进入五步配置向导。
4. 完成全量体检并保存。主进程检测到正式配置提交后，会自动继续启动钉钉机器人，无需再次运行 EXE。

配置文件完全不存在时也可以进入向导。已有 V2.15 完整配置会直接进入工作台，不会强制重新配置；如果后来清空了钉钉凭证，则会重新进入向导。

服务器或自动化部署可临时使用环境变量 `OPSPILOT_ADMIN_PORT` 指定本机管理端口，并用 `OPSPILOT_ADMIN_AUTO_OPEN=false` 禁止自动打开浏览器；它们只覆盖本次进程，不写回配置文件。

## 五步向导

### 1. 选择用途

- 运维服务台：推荐启用工单、知识闭环、表格、图片和语音；缺少依赖的可选模块不会被强行开启。
- 轻量工单：优先启用工单受理与流转。
- 知识助手：优先启用知识、图片和语音。
- 自定义：自行选择模块。

用途只影响推荐开关，完成后可以在设置中修改。

### 2. 连接钉钉

填写 Client ID 与 Client Secret，可选填写 Agent ID。点击“测试钉钉连接”后才会调用钉钉接口。Secret 只在当前进程内的向导草稿中暂存，不写入 `.setup-draft.yaml`，状态接口只返回 `has_client_secret`。

### 3. 连接 AI

可选择 DeepSeek、OpenAI 兼容服务、Ollama、其他本地兼容服务或暂不启用 AI。DeepSeek 和普通云服务需要 API Key；明确选择 Ollama/本地服务时允许无 Key，HTTP 请求也不会携带空的 Authorization 头。

更换服务商或 Base URL 且没有填写新 Key 时，系统会清除旧 Key，避免将一个服务商的凭证发送到另一个地址。

向导中的默认 AI 会自动作为未单独路由时的默认模型，包括图片识别。要启用图片识别，所选模型本身必须支持 OpenAI 兼容的 `image_url` 图片输入；普通纯文本模型虽然能通过基础连通性检查，但实际不能理解图片。需要区分问答和视觉模型时，可在高级模式的“模型路由”中单独指定 `vision`。

### 4. 选择模块

模块统一显示启用、已配置、可用和依赖状态：

- 工单中心
- 知识闭环
- 表格助手
- 图片识别
- 语音识别
- 钉钉智能表格

语音消息优先使用钉钉自带的识别文本，本地 Whisper 仅作为可选备用。关闭图片识别后仍可把图片作为工单附件保存，但不会调用视觉模型；关闭语音识别后会明确提示改用文字。表格助手只有检测到 Node.js 与 `@oai/artifact-tool` 才能启用；智能表格同步还需要工单模块、`dws`、Base ID 和 Table ID。

模块开关控制实际运行链路，不只是隐藏页面。关闭工单后不会再查询、创建或挂接工单，也不会启动逾期提醒、周报、回访、日报和智能表格同步；关闭工单、表格和图片能力时，普通附件会在下载前直接拒绝。运行中的机器人修改模块后按页面提示重启，确保后台线程与新状态一致。

### 5. 团队与体检

可以添加一位负责人，填写姓名和钉钉 Staff ID。完成按钮会执行钉钉、AI、数据目录和已选模块的全量检查；模块依赖未就绪时服务端也会拒绝提交，可先关闭该可选模块后继续。

## 日常操作台

默认一级入口：

- 首页：待办、逾期、SLA 风险、通知失败和快捷操作。
- 工单：查询、分派、处理、解决、批量操作和服务目录关联。
- 知识：审核候选、处理知识缺口和查看来源效果。
- 文件与任务：文件助手说明、最近后台任务和智能表格状态。
- 设置：重新运行向导、模块开关、人员、回答方式、连接器和维护工具。

简单模式默认隐藏 Base URL、接口路径、JSON 映射、运行路径、Token、超时和并发等技术字段。需要定制时在设置页开启“高级模式”，该选项只影响本机显示，不构成权限控制。

## 安全配置包

设置页提供“导出安全配置包”和“导入配置包”：

- 导出为 JSON，包含公共配置、人员、服务目录和回答策略。
- 自动移除 Secret、API Key、密码、认证 Header、本机绝对路径及首次完成标记。
- 导入前显示受影响的配置区域和仍需补充的凭证。
- 导入使用合并方式；只有服务商、端点或连接器身份未改变时，空白密钥才会保留目标机器已有值，换绑会主动清除旧凭证。
- 应用前写入可回滚快照，成功后再记录一次结果快照；运行期对象需重启后全部采用新配置。

工单数据库、知识数据库、日志、附件和运行历史不属于配置包。它们需要独立的数据备份与迁移流程。

## 发行规则

`build.py` 只从 `config.example.yaml` 生成 `dist/dingtalk-ops-v2.16.0-package/config.yaml`，禁止复制开发环境的正式配置。可交付内容仅限该 package 子目录，不能发送包含运行数据的 `dist` 根目录。脚本只允许 EXE、`config.yaml` 和首次使用说明三个文件；若目标目录已有额外文件、数据目录或已填写配置，会拒绝自动清理。模板必须满足：

- 钉钉、IMA、LLM、CodeBuddy 凭证为空。
- 人员、接收人和知识库列表为空。
- 不包含 Windows 绝对路径、UNC 路径或企业专属标识。
- 数据库、日志和导出目录只使用相对路径。

## 验收清单

- 删除配置文件后仍能打开本机向导。
- 空白模板启动时不尝试连接钉钉 Stream。
- 向导草稿和所有 GET 接口均不回显密钥。
- 已有完整配置无需重新向导。
- 五个一级入口和所有原功能二级入口均可访问。
- 普通模式不显示 JSON、路径和并发参数。
- 本地模型可在无 Key 场景完成测试和实际调用。
- 模块开关与消息处理行为一致。
- 安全配置包中不含现用密钥和本机绝对路径。
- 发行目录恰好三个白名单文件，EXE 具有有效 Windows 头、合理体积和已记录 SHA-256。
- 单元回归、旧工单脚本、Python 编译、JavaScript 语法和 EXE 空白启动全部通过。
